One command instead of a pipeline

The same jobs, without remembering which flags lsof needs or piping PIDs into kill.

What's on port 3000?lsof -i :3000 -P -nproc on :3000
Why is it there?lsof -i :3000, then ps -o ppid= up the chainproc why :3000
Free the portlsof -t -i:3000 | xargs kill && sleep 1 && lsof -i:3000proc free :3000
Wait for it to exitwhile ps aux | grep node | grep -v grep; do sleep 5; doneproc wait node
Pause a processkill -STOP $(pgrep node)proc freeze node
Find leftoversNo standard toolproc orphans --in .

Nineteen commands, three jobs

Every command takes the same targets, and almost all take --in to stay inside one project, --json for scripts, and --dry-run before anything changes.

Find out

Read-only. Nothing is touched.

  • on :3000what's on a port
  • why :3000what started it
  • in .started in this folder
  • by nodeby name
  • for ./app.jsrunning a file
  • info 1234everything about one
  • portsall listening ports
  • treeparents and children

Change it

Asks first, or previews with --dry-run.

  • stop nodeask it to exit
  • kill :3000end it now
  • free :3000and check it's free
  • freeze nodepause
  • thaw noderesume
  • unstickrecover a stuck process

All commands and options

Made for scripts and coding agents

Every command prints JSON with --json (one document per command; watch streams one per refresh), and exit codes always mean the same thing. An agent can read proc the way you do, without parsing tables.

  • 0 success, 1 error, 2 not found, 3 permission denied, 4 invalid input
  • --dry-run shows what would be touched, and nothing else
  • The agent skill teaches Claude Code, Codex, Cursor, Gemini CLI and others when to reach for proc
